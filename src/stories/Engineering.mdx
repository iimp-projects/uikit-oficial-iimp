# Bootstrap y Zero Errors

El ecosistema IIMP separa tres responsabilidades:

1. `official-uikit-iimp`: componentes, tokens, layouts y configuración compartida.
2. `iimp-next-starter`: inicio limpio para aplicaciones nuevas.
3. `@nrivera-iimp/adopt`: adopción segura para aplicaciones existentes.

## Proyecto nuevo

```bash
npx create-next-app@latest \
  --example "https://github.com/iimp-projects/uikit-oficial-iimp" \
  --example-path templates/next-starter \
  mi-proyecto

cd mi-proyecto
npm run setup
npm run check
```

## Proyecto existente

```bash
npx @nrivera-iimp/adopt@latest --dry-run
npx @nrivera-iimp/adopt@latest
npm run check
```

## Contrato de calidad

- TypeScript strict.
- ESLint type-aware y Core Web Vitals.
- Guardrails que exigen componentes oficiales.
- Cero warnings.
- Formato, pruebas y build en cada PR.
- Migraciones visuales sin cambios de negocio.

## Skills

El setup instala solo las skills faltantes. Después analiza el stack y presenta una lista consolidada de recomendaciones; el desarrollador puede instalar todas, algunas o ninguna sin elegir categorías previamente. Las skills se instalan para los agentes compatibles, incluidos Codex, Claude y Gemini, y se detectan previamente en `.agents/skills`, `.codex/skills`, `.claude/skills` y `.gemini/skills`.

## Bitácora compartida

El starter y la adopción completa crean `bitacora.md`. Antes de continuar, Codex, Claude y Gemini leen el historial; al cerrar un avance relevante, agregan fecha/hora America/Lima, cambio y validación sin reescribir entradas previas.

```bash
npm run bitacora -- "Se terminó el ajuste y npm run check pasó."
```

`AGENTS.md` contiene el contrato común y `CLAUDE.md`/`GEMINI.md` lo hacen explícito para cada agente.

## Actualizaciones

El starter se copia una sola vez. El UI Kit se actualiza por npm y no sobrescribe páginas, props, acciones o lógica del proyecto consumidor. Las actualizaciones mayores de Next.js entran mediante PR y deben superar `npm run check`.
